# Findings from the 2026-10-05 runs, and follow-ups

From the 65 scripted class A runs in `eval/runs/2026-10-05` (Linux, Playwright 1.63 and Patchright 1.63 builds of Chromium 153, headful runs under Xvfb, ruleset 2026.10.1), plus the 16 Browser Use runs added the same day (item 6). The gate result is in [gate-2026-10-05.md](gate-2026-10-05.md). No signal, rule or threshold was changed in M2; each item below is a follow-up for a later ruleset, to be decided with human data in hand.

1. **Headful Playwright reports `navigator.webdriver === true`.** Architecture section 1 expected current headful Playwright to report `false` and be caught only by behaviour. With Playwright 1.63 all 15 headful runs, and all 10 Playwright + ghost-cursor runs, fired the `webdriver` Tier 1 rule. This is the M0 "headful Playwright runtime tell" check answered for this version; it may change with Playwright releases, so the monthly marker re-run (M3) should cover it.
2. **Patchright is caught only by behaviour, and never attributed.** All 15 stock Patchright runs ended `agent-unattributed` on R1/R2 (single-move clicks) plus R7 (centre clicks), once with R6. No Tier 1 rule fired, and the class A profile (a pointer-media or platform tell) never matched. Both baselines missed every Patchright run. These rules have no human false-positive data yet, so this recall is not a claim until the 7.3 sessions exist.
3. **A humanised pointer on Patchright evades everything here.** Patchright + ghost-cursor ended `human-like` in 10/10 runs, as did BotD and agent-detector. Expected (architecture section 1); published as a known gap.
4. **R5 never fires on Playwright `fill()`.** In every run the six `fill()` calls arrived as value jumps with no keystrokes: four as trusted keyless `insertText` (the dictation and Voice Control path R5 abstains on) and two in the autofill-hinted fields (its autofill path), so `fillFields` stayed 0, as architecture 5.1 predicted. No change proposed: closing it would cost those users.
5. **R6's no-input-scroll clause barely registers here.** Playwright's own scroll-into-view counted as a no-input scroll in 8 of 30 Playwright runs and 8 of 15 Patchright runs, and R6 needs two that are each followed by a click within 1 s: that happened in one run (Patchright, which fired R6 with "2 no-input scrolls followed by a click"). Browser Use recorded at most one no-input scroll per run (in 5 of its 16 runs), so R6 never fired there either. Container no-input scrolls remain the hypothesis the architecture names, waiting on computer-use runs.
6. **Stock Browser Use is caught by its own Tier 1 markers.** 16 runs of browser-use 0.13.10 (highlights on) driven by Claude Sonnet 5 through OpenRouter, Playwright's Chromium 153; run 01 ran headless because Browser Use found no screen, runs 02-16 headful under Xvfb. All 16 reached the last page and ended `agent-likely`, class A, `certain`, on `BU-marker` (its highlight attributes) and `BU-trio` (six synthetic input/change/blur trios in every run); run 01 also fired `headless-ua`. BotD flagged only the headless run (1/16); agent-detector flagged all 16. Claude Opus 5.5, the runner's default model, could not drive Browser Use at all: it declines Browser Use's agent prompt (`refusal`, category `reasoning_extraction`).

Not yet measured at all: computer-use-demo (class B; OpenRouter rejects the Anthropic computer-use tool, so these runs need a direct Anthropic key and Docker), any class C agent, and every human and assistive-technology cohort. [harness/README.md](../../harness/README.md) has the runbooks.
