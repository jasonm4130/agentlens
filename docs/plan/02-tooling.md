# 02 — Tooling survey: agent-vs-human detection (as of 2026-10-02)

Scope: a lightweight, ideally OSS, in-page detector for our own site that separates AI agents from humans. Agent classes used throughout:

- **A**: CDP/Playwright/Puppeteer-driven browsers (Browser Use, Stagehand, Browserbase, hosted Operator-style).
- **B**: OS-level computer use (screenshot, then model, then xdotool in a VM). Its events are real and `isTrusted`.
- **C**: extension or built-in agents running in the user's real browser (Claude in Chrome, ChatGPT Atlas, Perplexity Comet, Gemini in Chrome).

Verification key: "gh verified" means the figure came from `gh api repos/...` during this pass. "200" means the URL returned HTTP 200 to curl but the content was not re-read. **UNVERIFIED** means the claim was carried over from an earlier list or a vendor page and not checked here.

---

## 1. Bottom line

**No mature OSS project does "agent vs human" well across all three classes.** Class A is a solved commodity: fpscanner, BotD, CreepJS and Brotector all catch unpatched automation, and patched stacks (Patchright, Camoufox) defeat them. Class C has one young detector and one lab that document fragile, vendor-specific page markers. Class B has **no OSS signal**, and superliaye's lab says outright that it found "no known signal" for Codex Computer Use or default Playwright MCP.

The closest match is **doubleagent-so/agent-detector** (MIT, zero-dependency TS, claims ≤16 KB gzip, fuses probes with pointer, key and scroll timing). It was created on 2026-09-27, has 0 stars, and its class B/C strength is not evidenced. A grep of its README found no computer-use, xdotool or trusted-event wording, and its size claim is a badge we did not measure.

**Recommendation: build our own, reusing specific parts.**

- **Build** the behavioural and temporal layer, which is aimed at classes B and C and is the project's real value. Also build the eval harness and the scoring and policy layer.
- **Reuse or port** the class A probe layer (fpscanner's checks and its anti-replay payload pattern, plus BotD's checks). Take techniques from CreepJS and Brotector. Read agent-detector as a reference design and benchmark against it, but do not take a dependency on it yet.
- **Reuse** the declared-agent lane: cloudflare/web-bot-auth (Apache-2.0) to verify RFC 9421 signatures, and arcjet/well-known-bots (MIT) for user-agent catalogs.
- **Reuse** ALTCHA (MIT) as an optional escalation step. Proof of work does not detect agents; it only adds cost.

## 4. Research, datasets and traffic-generation harnesses

### Papers (most relevant first)

- **What Does It Take to Detect an AI Agent?** [arXiv 2607.26935](https://arxiv.org/abs/2607.26935) (200). Claims mouse-event rate plus teleport-click ratio separates human, bot and agent with tree models. Strong on A; per the abstract it does not handle B/C (UNVERIFIED beyond the abstract). Use it as the blueprint for the cheapest feature set, and treat its class A result as the trivial baseline we must beat.
- **Known By Their Actions** [arXiv 2605.14786](https://arxiv.org/abs/2605.14786) (200) plus [KabakaWilliam/known_actions](https://github.com/KabakaWilliam/known_actions) (no licence; pushed 2026-09-06; 7★). Passive JS tracker with XGBoost that identifies _which_ LLM drives an agent (claims up to 96% F1 across 14 LLMs). It is a labelled LLM-agent trace corpus, but its reuse terms are unclear.
- **Whose Agent Are You?** [arXiv 2606.20910](https://arxiv.org/abs/2606.20910) (200). HTTP, TLS and action fingerprints; claims 97% decision-tree accuracy. Reference for server-side features; release of code and data is unconfirmed.
- **Detecting Bot Detection** (Bamberg, ARES 2026), [project page](https://psi.uni-bamberg.de/en/forschung/bot-detection/) (200). Measures how often sites block automated browsers, giving base rates and a reproducible crawler. The Zenodo artefact was not opened.
- **BrowserArena** [arXiv 2510.02418](https://arxiv.org/abs/2510.02418) (200). Behavioural differences between agents on the live web, as feature ideas.
- **Proof of Human: CAPTCHAs can still detect AI agents** ([research.poh.org](https://research.poh.org/), 200). Vendor study of how Claude, Gemini and GPT agents behave on reCAPTCHA v2. It is the closest public work on vision-driven input versus humans, so **read it before designing B/C signals.** Numbers not read; the vendor has a commercial interest.
- **Iliou et al.**, web logs plus mouse biometrics, [Zenodo 5549439](https://zenodo.org/record/5549439). A decision-fusion architecture. Zenodo returned 403 to curl, so the CC BY 4.0 licence is UNVERIFIED.
- [niespodd/browser-fingerprinting](https://github.com/niespodd/browser-fingerprinting) (no licence; 5146★; pushed 2026-07-27). Practitioner notes on commercial anti-bot detection and evasion, useful as a reading list. Agent-specific content UNVERIFIED.
- [SplxAI: ChatGPT Agent passes Cloudflare check](https://splx.ai/blog/chatgpt-agent-solves-captcha) (200). Eval case showing that passing a challenge is not proof of humanity.

## 6. Gaps no existing tool fills (where this project adds value)

1. **Class B detection.** No OSS tool has an evidenced signal for OS-level computer use, whose events are real and `isTrusted`. The superliaye lab reports "no known signal" for Codex Computer Use and default Playwright MCP. Candidate signals are hypotheses until tested on our own traces:
   - the screenshot-act loop's cadence: bursty actions separated by multi-second think gaps;
   - pointer teleports, or straight xdotool paths with no sub-movement corrections;
   - no hover, scroll or idle micro-movement between actions;
   - typing at a uniform inter-key interval;
   - VM, renderer and screen fingerprints (llvmpipe/SwiftShader, fixed 1024x768-style viewports).
2. **Robust class C detection.** Today's class C detection rests on vendor-specific DOM or extension markers, which are fragile and break on vendor updates. Nothing models the _behavioural_ side of an agent sharing a human's browser: mixed-control sessions in which a human hands off to an agent mid-session.
3. **Labelled datasets for B and C.** Every public mouse dataset is either human-only or pre-LLM synthetic. A reproducible harness that emits labelled A/B/C/human sessions against an instrumented page (claude-quickstarts, OSWorld, Browser Use, Patchright/Camoufox, ghost-cursor, plus recorded humans) would be valuable on its own.
4. **An open, lightweight, session-level scorer.** Precursor-style session scoring exists only in closed products. The only OSS attempt (agent-detector) is 5 days old and unproven on B/C.
5. **Calibrated outputs and policy.** OSS tools return a boolean (`bot: true`). None returns a calibrated _agent-vs-human_ probability with per-class attribution, confidence that rises over the session, and a policy hook (allow signed agents, challenge with ALTCHA, label for analytics).
6. **A standing adversarial benchmark.** No public scoreboard tracks the agents of 2026 (classes A, B and C) against detectors over time. The rebrowser and incolumitas pages are class A only and partly dormant.
